### INC-05220  [↗](/incident/INC-05220.html)

**TensorFlow — Dos (CVE-2022-29191)**  
_2022-05 · vulnerability-disclosure · Severity: High_

CVEs: `CVE-2021-41228`, `CVE-2022-23567`, `CVE-2022-23569`, `CVE-2022-29191`, `CVE-2022-29192`, `CVE-2022-29193`, `CVE-2022-29194`, `CVE-2022-29195`, `CVE-2022-29196`, `CVE-2022-29197`, `CVE-2022-29198`, `CVE-2022-29199`, `CVE-2022-29200`, `CVE-2022-29201`, `CVE-2022-29202`, `CVE-2022-29203`, `CVE-2022-29204`, `CVE-2022-29205`, `CVE-2022-29206`, `CVE-2022-29207`, `CVE-2022-29208`, `CVE-2022-29209`, `CVE-2022-29210`, `CVE-2022-29211`, `CVE-2022-29212`, `CVE-2022-29213`, `CVE-2022-29216`
CVSS: **5.5**

TensorFlow is an open source platform for machine learning. Prior to versions 2.9.0, 2.8.1, 2.7.2, and 2.6.4, the implementation of `tf.raw_ops.GetSessionTensor` does not fully validate the input arguments. This results in a `CHECK`-failure which can be used to trigger a denial of service attack. Versions 2.9.0, 2.8.1, 2.7.2, and 2.6.4 contain a patch for this issue.

**Affected:** google/tensorflow  
**Attack vector:** `dos`

**NIST AI RMF:** `GOVERN-6.1`, `MEASURE-2.7`
