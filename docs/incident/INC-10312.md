### INC-10312  [↗](/incident/INC-10312.html)

**content-security-policy-parser Prototype Pollution Vulnerability May Lead to RCE**  
_2025-08 · vulnerability-disclosure · Severity: High_

CVEs: `CVE-2025-55164`
CWEs: `CWE-1321`

### Impact A prototype pollution vulnerability exists in versions 0.5.0 and earlier, wherein if you provide a policy name called `__proto__` you can override the Object prototype. For example: ``` const parse = require('content-security-policy-parser'); const x = parse("default-src 'self'; __proto__ foobar"); console.log('raw print:', x); console.log('toString:', x.toString()); ``` Outputs: ``` raw print: Array { 'default-src': [ "'self'" ] } toString: foobar ``` Whilst no gadget exists in this library, it is possible via other libraries expose functionality that enable RCE. It is customary to label prototype pollution vulnerabilities in this way. The most common effect of this is denial of service, as you can trivially overwrite properties. As the content security policy is provided in HTTP queries, it is incredibly likely that network exploitation is possible. ### Patches There has been a patch implemented a year ago (11 Feb 2024), but low uptake of patched versions has not been observed in the wild - only 17% of weekly downloads are of patched versions. ### Workarounds By disabling prototype method in NodeJS you can neutralise all possible prototype pollution attacks.
