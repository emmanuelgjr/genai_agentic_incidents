# WS0-T3 AIAAIC Reduction — Silent Taxonomy Cascade

**Audit date:** 2026-07-18
**Branch:** `ws0/t3-aiaaic-reduction`
**Baseline (HEAD):** `a2d7a26e` (schema fields `description_provenance` + `description_source`, per D9)
**Subject:** An ungated rebuild produced by the D9-approved AIAAIC description
field-cut. The rebuild was measured against HEAD **before** being discarded via
`git restore`; this file is that measurement, preserved as evidence for WS2
label-quality work, WS1-T6 source-bias, and the eventual governance write-up.

> **Status of the data:** the rebuild described here was **discarded** (`git
> restore .`) immediately after this audit was committed. The corpus on
> `main`/HEAD is unaffected. This document records what the cut *would have*
> published had it been committed ungated.

---

## 1. What the cut was supposed to do

Per **D2** (AIAAIC = facts + link) and **D9** (field cut approved), the AIAAIC
per-row `description` was rebuilt to carry **only categorical facts** —
`system` · `technology` · `sector` · `jurisdiction` — and to **drop** AIAAIC's
four editorial-prose cells: `purpose` · `ethical` · `consequence` · `response`
(the CC BY-SA-protected original expression). Example target form:

```
AIAAIC-tracked incident. System: X. Technology: Y. Sector: Z. Jurisdiction: W.
```

This licensing objective was achieved cleanly: a full scan of all 1,513
AIAAIC-derived entries in the rebuilt tree found **0** descriptions still
carrying any dropped-cell marker (`Purpose:` / `Ethical issues:` /
`Reported consequences:` / `Response:` / the old `AIAAIC report:` prefix).

## 2. What the cut actually also did (the defect)

The D9 spec treated the field-cut as a **pure licensing operation**. It is not.
Two independent heuristic mappers in the deterministic build path read the
**published `description` text** — the very text the cut rewrote — and both
silently re-derived corpus/taxonomy labels from it. Removing the editorial
prose therefore silently **relabelled the corpus**.

Two distinct derivation paths, each rooted in the same prose removal:

- **Path A — attack_vector → framework taxonomy** (§4): 221 `attack_vector`
  changes → 88 entries lose `owasp_llm`/`mitre_atlas`/`mitre_atlas_tactics`/
  `nist_ai_rmf` mappings.
- **Path B — corpus → landmark tier** (§5): 164 `corpus` flips `ai-harm →
  security` → published statistic `landmark_count` moves **1865 → 1701**.

**372 distinct entries** were touched across both paths (overlap 13).
**Every one is AIAAIC-derived; 0 are non-AIAAIC.**

## 4. Root-cause trace — Path A (attack_vector → taxonomy)

All references `scripts/merge_and_dedupe.py`.

1. **`classify_attack_vector()` keyword table (`:419`)** contains
   `(r"misinform|disinform", "misinformation")`. This classifier reads
   **title + description** text.
2. **Finalize/reclassify block (`:1282–1305`)** re-runs
   `classify_attack_vector((title or "") + " " + (description or ""))` on every
   entry still sitting at `attack_vector == "other"`, upgrading it if the text
   matches.
   - In HEAD, the AIAAIC description carried `Ethical issues: Mis/disinformation`
     → matched `disinform` → `attack_vector = "misinformation"`.
   - After the cut the ethical cell is gone → no `disinform`/`misinform` in the
     text → the entry stays `"other"`. **→ 216 entries flip
     `misinformation → other`.**
3. **Framework seed map (`:270`)**: `_VECTOR_TO_OWASP_LLM` maps
   `"misinformation": ["LLM09"]`. Applied by **`seed_frameworks_from_vector()`
   (`:287`)**, which seeds OWASP/NIST/ATLAS from the finalized `attack_vector`
   **only for entries with no framework mapping at all**.
   - With `attack_vector` no longer `"misinformation"`, the seed no longer
     fires for those entries. The 88 that had *only* this seed-derived mapping
     lose `LLM09`.
4. **`fill_taxonomy()` (`:640`)** cascades the (now absent) `LLM09` onward:
   `LLM09 → AML.T0058` (`mitre_atlas`, seen at `:232`) and
   `LLM09 → MEASURE-2.8` (`nist_ai_rmf`, `:244`). **→ 88 entries lose
   `owasp_llm` + `mitre_atlas` + `mitre_atlas_tactics` + `nist_ai_rmf`
   together.**

The 88 `owasp_llm` losses are a strict subset of the 221 `attack_vector`
changes (confirmed: `owasp ⊆ attack_vector`). The other ~133 attack_vector
changes kept their OWASP code because they already had a non-seed mapping
(`seed_frameworks_from_vector` never overrides an existing mapping).

### Worked example — INC-01149 (`AIAAIC2246`)

```
attack_vector:  misinformation  ->  other
owasp_llm:      ['LLM05']       ->  ['LLM05']   (already mapped; seed did not fire)

HEAD desc: "AIAAIC report: Grok generates offensive posts about Hillsborough,
            Heysel football disasters. System: Grok. Technology: Generative AI.
            Purpose: Ridicule football clubs. Ethical issues: Mis/disinformation;
            Safety."
WORK desc: "AIAAIC-tracked incident. System: Grok. Technology: Generative AI.
            Sector: Media/entertainment/sports/arts. Jurisdiction: UK."
```

The token `Mis/disinformation` present in HEAD's `Ethical issues:` clause is the
sole reason `attack_vector` read `misinformation`. The cut removed it; the label
collapsed to `other`.

## 5. Root-cause trace — Path B (corpus → landmark, the `landmark_count` −164)

`landmark_count` matches neither 221 nor 88 because it is a **third, separate
derivation path**.

1. **`landmark_count` (`scripts/render_markdown.py:514`)** =
   `sum(1 for e in entries if e.get("tier") == "landmark")`.
2. **`_derive_tier()` (`merge_and_dedupe.py:161`)**: an entry is `landmark` iff
   `quality_tier == "curated"` **OR** `aiid_id` present **OR**
   `corpus == "ai-harm"`; otherwise `feed`.
3. **`_classify_corpus()` (`:534`, applied at `:1358`)** reads
   **title + description + tags** text. It returns `ai-harm` only if the text
   contains an AI-harm keyword from `_AI_HARM_KEYWORDS` (`:518`) — e.g.
   `"discriminat"`, `"racial bias"`, `"gender bias"`, `"fairness"`,
   `"algorithmic bias"` — and no security keyword wins first; otherwise it
   defaults to `security`.
   - Those harm keywords lived in AIAAIC's **`ethical` cell** (e.g.
     `Ethical issues: Bias/discrimination; ...`).
   - The cut removed the ethical cell → the harm keyword vanishes from the
     description → `has_harm` is false → `corpus` falls through to `security`.
4. For an auto/reviewed-tier entry with no `aiid_id`, losing `corpus ==
   "ai-harm"` means losing its **only** landmark qualifier. **→ 164 entries
   drop out of the landmark tier → `landmark_count: 1865 → 1701`.**

### Worked example — INC-00716 (`AIAAIC2192`)

```
corpus:        ai-harm  ->  security     (=> drops out of landmark tier)
attack_vector: other    ->  other        (no security keyword either)
owasp_llm:     ['LLM06','LLM07'] unchanged

HEAD desc: "AIAAIC report: British Museum AI-generated \"visitors\" spark fury.
            Technology: Generative AI. Purpose: Create marketing images.
            Ethical issues: Accountability; Bias/discrimination; Employment/labour;
            Normalisation; Representation; Transparency. Response: Content takedown."
WORK desc: "AIAAIC-tracked incident. Technology: Generative AI.
            Sector: Media/entertainment/sports/arts. Jurisdiction: UK."
```

`Bias/discrimination` in HEAD's `Ethical issues:` clause matched
`_AI_HARM_KEYWORDS` (`"discriminat"`). Removing the ethical cell reclassified
the entry to `security` and silently demoted it from the published landmark
count.

## 6. The load-bearing finding for WS2 / WS1

**The pre-cut `LLM09`/`ATLAS`/`NIST` mappings and the `ai-harm` corpus
assignments on these entries were never independent analytic findings. They
were mechanically derived from AIAAIC's own editorial vocabulary** — the
`Mis/disinformation` and `Bias/discrimination` strings in AIAAIC's `ethical`
cell — via keyword match. The mapping was, in effect, *"AIAAIC's editors
called this misinformation, therefore we tag it LLM09."*

Consequences that outlive this branch:

- **~88-entry population** carries `LLM09` (+ cascaded ATLAS `AML.T0058` / NIST
  `MEASURE-2.8`) whose provenance is **source-derived from AIAAIC's
  ethical-issues cell**, not an independent mapping judgment. WS2-T3 must tag
  these `method: source-derived`; WS2-T2's two-annotator study must stratify on
  them separately.
- **AIAAIC editorial vocabulary materially shapes the `misinformation`
  attack_vector distribution** (216 entries hinge on the single `disinform`
  token) — a **WS1-T6 source-bias** signal and a **WS2-T4 `other`-bucket**
  input: the size of the `other` bucket for AIAAIC rows is an artifact of which
  AIAAIC ethical labels happen to contain matched keywords.

These are logged as WS2/WS1 board inputs on `PROGRESS.md`.

## 7. Remediation (implemented as the re-scoped WS0-T3 spec)

The licensing cut is correct; the coupling to the published prose is the defect.
The fix decouples label derivation from the published `description`:

- The mapping/corpus seed must read AIAAIC's **structured cells from the ingest
  row** (which retains the `ethical` cell internally) **before** description
  composition — never from the published, prose-stripped `description`.
- A regression test must assert the seed does not depend on published
  `description` text.
- Acceptance gains a hard gate: a full field-level before/after delta (this
  document's shape) with **zero unintended deltas**; any intended delta
  enumerated and justified.

See the re-scoped WS0-T3 row and the D9-correction note on `PROGRESS.md`.
